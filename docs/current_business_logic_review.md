# 当前 Video Manager 实现与业务逻辑审查

## 实现结构

- `cmd/video-manager`：Windows GUI 入口。
- `internal/ui`：原生 Win32 深色 UI、后台任务调度、进度、日志、Dry-run 分页和配置状态管理。
- `internal/appconfig`：在 EXE 同目录的 `data/config.json` 原子保存配置。
- `internal/archive/scanner.go`：递归扫描固定视频后缀，排除目标目录和系统目录。
- `internal/archive/capacity.go`：按任意 1 至 5 层目录结构计算容量和预览路径。
- `internal/archive/planner.go`：生成稳定移动计划、检查目标目录、解决重名并导出 TSV。
- `internal/archive/mover.go`：同盘优先重命名；失败后复制、校验、删除，生成可撤销清单。
- `internal/archive/undo.go` / `cleanup.go`：撤销最近运行与清理源目录中的空目录。

## 原项目主业务流程

1. 用户设置源目录、目标目录、目录层数、各层名称和数量、每叶目录文件数。
2. 扫描器递归识别固定视频后缀并记录大小、修改时间、相对路径和扩展名。
3. 文件按修改时间升序排列；时间相同按相对路径、文件名和完整路径排序。
4. 容量计算器计算叶目录需求、最后叶目录、各层实际数量和最大容量。
5. Dry-run 校验目标可访问性，生成每个文件的目标路径；容量不足时只扩展第一层目录数量。
6. 目标重名使用 `_dupNNN`，计划同时导出到程序数据目录的 TSV。
7. 用户确认后执行移动。每个文件移动前复核扫描时的大小与修改时间。
8. 同盘优先 `rename`；失败或跨盘时按块复制，校验大小和时间后删除源文件。
9. 成功项写入运行清单，移动结束后清理空源目录；清单可用于撤销最近一次移动。

## 设计评价

优点：

- 核心文件操作与 UI 解耦，关键规则有自动化测试。
- 扫描、Dry-run、移动和撤销均在后台执行，Win32 消息线程保持响应。
- 正式移动前必须经过 Dry-run，且配置变化会让旧计划失效。
- 对跨盘、网络路径、源文件变化、重名和撤销均有防护。

需要留意：

- 原扫描后缀是代码内固定集合，不适合任意文件格式。
- 原容量模型是通用层级计数，不表达年份、季度和月份之间的日历关系。
- UI 文件集中承载较多 Win32 控件、状态和任务代码，后续可按窗口状态、任务控制和视图组件进一步拆分。

本仓库新增的 `file-manager` 子项目针对前两项限制增加了可配置后缀和固定日历目录模型，同时复用原项目的正式移动、清理和撤销链路。
