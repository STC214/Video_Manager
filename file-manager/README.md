# File Manager

`File Manager` 是 `Video Manager` 仓库内的独立子项目。它沿用原项目的原生 Win32 深色 UI 和安全移动流程，用可配置文件后缀整理任意类型的文件。

## 目录层级和命名（新手也可以直接照着设置）

程序不再要求用户直接填写一整串抽象模板。主窗口中按下面的顺序操作即可：

1. 在“目录层数”中输入 `1` 到 `8`。这里的层数是目标目录下面还要建立几层文件夹。
2. 点击右侧的“应用层数”。程序会在下面显示“第 1 层”“第 2 层”等设置行，并填入适合该层数的常用默认方案。
3. 在每一行的下拉框中选择命名方式。右侧会立即显示用途说明和生成结果示例。
4. 选择“固定名称”或“自定义规则（高级）”时，在同一行右侧的输入框填写内容。
5. 查看“计算结果”，确认目录层数和示例路径符合预期，然后重新生成 Dry-run。已有 Dry-run 在设置变化后会自动失效，避免按旧结构移动文件。

> 再次点击“应用层数”会按当前层数重新生成一套常用默认选项。请先确定层数，再调整每层名称。

### 下拉框中的命名选项

| 选项 | 实际示例 | 适合放在哪里 |
| --- | --- | --- |
| 年份 | `2026` | 通常是第 1 层 |
| 季度 | `2026S1` | 可以是中间层，也可以直接作为最后一层；不需要季度时不选择它 |
| 月份 | `202601` | 通常放在季度下面；没有季度时可直接放在年份下面 |
| 月内分组 | `20260101` | 通常是最后一层；末尾 `01` 表示当月第 1 组 |
| 简洁分组 | `第01组` | 也是最后一层的常用选择，文字更容易阅读 |
| 固定名称 | `作品归档` | 任意中间层；输入什么名称，每个位置就固定使用什么名称 |
| 自定义规则（高级） | 由填写内容决定 | 只在常用选项满足不了需求时使用 |

数量选项会跟着当前规则自动调整：

- 最后一层含“月内分组”或 `{NN}` 时，显示“每月份分组数”；例如每月 4 组、每目录 30 个文件，一个月可容纳 120 个文件。
- 最细时间单位是季度且仍含 `{NN}` 时，自动改为“每季度分组数”。
- 如果最后一层就是年份、季度或月份，没有额外分组编号，分组数输入框会隐藏。此时“每目录文件数”直接表示每个年份、季度或月份目录可放多少个文件。

#### 两层：年份 → 季度

把目录层数设为 `2` 并点击“应用层数”。季度目录会直接作为最终文件容器，不会再要求月份或月内分组：

```text
目标目录/
  2026/
    2026S1/
    2026S2/
```

此时“每月份分组数”会自动隐藏，只需设置“每目录文件数”。例如填 `100`，每个季度目录最多放 100 个文件，满后自动进入下一个季度。

### 三个可以直接照抄的例子

#### 默认四层：年份 → 季度 → 月份 → 月内分组

把目录层数设为 `4` 并点击“应用层数”。默认会生成：

```text
目标目录/
  2026/
    2026S1/
      202601/
        20260101/
```

#### 不要季度：年份 → 月份 → 月内分组

最省事的方法是把目录层数设为 `3` 并点击“应用层数”。默认会生成：

```text
目标目录/
  2026/
    202601/
      20260101/
```

也可以保留其他层数，然后把原来的“季度”行改成其他选项。只要没有任何一行选择“季度”，就不会产生季度目录。

#### 五层并增加固定名称

把目录层数设为 `5` 并点击“应用层数”，再把第 2 层选择为“固定名称”，输入 `作品归档`：

```text
目标目录/
  2026/
    作品归档/
      2026S1/
        202601/
          20260101/
```

固定名称不能含有 Windows 文件夹禁止使用的字符，例如 `\ / : * ? " < > |`，也不要以空格或英文句点结尾。程序会在计算结果中提示错误。

### 自定义规则（高级）

普通用户使用前面的下拉选项即可。需要特殊样式时，可选择“自定义规则（高级）”，并在输入框中组合下面的变量和普通文字：

| 变量 | 意思 | 生成示例 |
| --- | --- | --- |
| `{YYYY}` | 四位年份 | `2026` |
| `{Q}` | 季度，范围 1 到 4 | `1` |
| `{MM}` | 两位月份 | `01` |
| `{NN}` | 两位月内分组编号 | `01` |

例如输入 `第{NN}组` 会生成 `第01组`，输入 `{YYYY}年第{MM}月` 会生成 `2026年第01月`。

整套目录规则必须满足以下条件，程序才能正确计算、追加投料、审计和撤销：

- 总层数为 1 到 8 层。
- 整套规则只强制要求年份 `{YYYY}`。季度 `{Q}`、月份 `{MM}` 和分组编号 `{NN}` 都可以根据实际需要省略。
- 程序以规则中最细的时间单位作为归档周期：有月份就是按月，没有月份但有季度就是按季度，只有年份就是按年。
- `{NN}` 最多使用一次；使用时必须放在最后一层。不使用 `{NN}` 时，最细的年份、季度或月份目录本身就是最终文件容器。
- 自定义内容不能生成空名称、`.`、`..`、Windows 保留名称或含非法字符的目录名。
- 每层生成的名称最长为 255 个 UTF-16 字符。

文件按最后修改时间从早到晚分配；时间相同则按相对路径和文件名稳定排序。所有层级设置同样用于普通扫描、投料、现有目标审计、重排和撤销。

## 后缀设置

支持逗号、分号、空格和中文标点分隔，大小写不敏感，点号可以省略，也支持 `.tar.gz` 等复合后缀。例如：

```text
.jpg, png；PDF
```

扫描只把这些后缀计为目标文件，其他文件只统计、不移动。多个后缀同时匹配时优先采用最长后缀。

## 工作流

1. 选择源目录和目标目录。
2. 设置后缀、起始年份、目录层数和每层命名方式；程序会按规则显示适用的周期分组数和每目录文件数。
3. 扫描，UI 自动显示目标文件数和容量计算结果。
4. 生成 Dry-run，检查分页预览和 TSV。
5. 确认后正式移动；需要时可按运行清单撤销最近一次移动。

目标重名会自动追加 `_dup001`。正式移动优先使用重命名；跨盘时使用复制、大小及时间校验后再删除源文件。

再次整理到已有目标目录时，Dry-run 会统计现有叶目录中的匹配文件，从第一个未满叶目录继续分配。正式移动每个文件前还会重新读取叶目录容量；若其他程序或网络用户在 Dry-run 后改变了容量，本次计划会停止并要求重新生成。

## 增量投料

“投料目录”用于选择本次新增文件的来源，投料文件使用同一套后缀和目录容量设置：

1. 选择投料目录后点击“投料 Dry-run”。
2. 程序先扫描投料文件，再审计目标目录中所有匹配后缀文件的位置和每叶数量。
3. 若目标结构正确，只把投料文件按修改时间从老到新追加到最后一个未满叶目录及后续新目录，不改变现有文件的位置。
4. 若目标结构存在错位、空洞、未填满的中间叶目录或超量叶目录，先把现有匹配文件经目标目录内的临时区按修改时间从老到新重排，再追加投料文件。
5. Dry-run 会显示投料数量、现有目标数量、整理后的目标总数、是否需要重排以及每次移动的完整 TSV 明细。

重排与投料共用一次运行清单，可整体撤销。若上次操作中断后临时区仍有文件，新投料会停止并提示先撤销或人工恢复，避免遗漏被暂存的文件。投料目录不能放在目标目录内部；目标目录可以位于投料目录内，此时扫描会自动排除目标子树。

正式移动前会在后台逐一校验全部投料源文件，并重新执行同一套目标审计，核对 Dry-run 时记录的目标文件路径、大小和修改时间快照；投料源或目标发生变化时不会移动任何文件，而是要求重新生成投料 Dry-run。这里的快照只用于判断计划是否过期，不改变上述“目录结构与每叶数量”的正确性边界。需要重排时采用失败即停策略：任一现有文件暂存或重排失败，后续操作立即停止，不会进入投料阶段。

运行清单采用预写记录：每次文件操作前先写入 `pending` 并执行文件同步，完成状态同样同步到磁盘。如果文件已经移动而完成记录因磁盘或网络故障未能写入，撤销会根据源和目标的实际状态恢复该操作；无法安全判断的歧义状态会停止自动撤销并保留恢复提示。新清单同时记录文件大小和完整范围的 RFC3339Nano 修改时间，撤销时两者都必须一致；旧版六列清单及上一版整数纳秒时间保持兼容。网络撤销读取清单和检查 `pending` 时会显示持续动画、采用网络重试并响应取消。

清单解析采用失败关闭策略：非法时间、非法大小、未知状态、列数不一致或截断记录都会阻止整次撤销，不会静默跳过或退回较弱校验。程序启动时先加载并显示普通配置，再在后台检查最近运行清单；网络检查显示动画，读取失败会写入日志，不会再阻塞路径和后缀配置的显示。

SMB、UNC 和网络映射盘的目录选择、扫描、校验及规划均在独立线程执行。目录选择器可通过主窗口取消，关闭程序也不会无限等待 Shell 对话框。扫描会逐层重试目录读取，包括网络暂时返回的“路径不存在”。网络 Dry-run 在目标规划和源目录空目录预览全部完成前保持持续动画；网络移动和撤销在单文件 I/O 期间也显示跑马灯。这些等待均不会阻塞主窗口消息循环。本机与网络盘之间的跨卷移动会跳过不可能成功的重命名长重试，直接使用 8 MiB 顺序缓冲复制，同时保留目标校验、落盘同步和撤销清单。

扫描被取消或存在任何目录读取错误时，结果会被视为不完整并禁止生成 Dry-run。跨盘复制会同步目标内容，设置后再次核验并同步目标文件的大小和修改时间，最后才删除源文件；网络空目录清理也逐层重试并持续显示读取动画。配置写入失败会显示在 UI 日志中，不再静默忽略。大型投料重排的审计和计划循环会持续检查取消信号，不会在目录读取停止后继续长时间生成计划。

预览和日志文本框按窗口宽度自动换行，不显示横向滚动条；两者单独使用略小字号以显示更多内容，不改变路径、配置、按钮和其他 UI 区域的字体。

## 构建与测试

在仓库根目录运行：

```powershell
go test ./file-manager/...
.\file-manager\build.ps1
```

构建输出为 `file-manager\dist\FileManager.exe`。运行配置保存在 EXE 同目录的 `file-manager-data\config.json`。
