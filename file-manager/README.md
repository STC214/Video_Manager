# File Manager

`File Manager` 是 `Video Manager` 仓库内的独立子项目。它沿用原项目的原生 Win32 深色 UI 和安全移动流程，用可配置文件后缀整理任意类型的文件。

## 目录规则

目录固定为四层：

```text
目标目录/
  2021/
    2021S3/
      202107/
        20210701/
```

- 第 1 层：从“起始年份”开始的四位年份。
- 第 2 层：该年份的季度，固定为 `YYYYS1` 到 `YYYYS4`。
- 第 3 层：月份，固定为 `YYYYMM`。
- 第 4 层：月内叶目录，固定为 `YYYYMMNN`，`NN` 从 `01` 开始。
- 每月叶目录数量全局统一设置。
- 每个叶目录的最大目标文件数量全局统一设置。
- 文件按最后修改时间从早到晚分配；时间相同则按相对路径和文件名稳定排序。

## 后缀设置

支持逗号、分号、空格和中文标点分隔，大小写不敏感，点号可以省略，也支持 `.tar.gz` 等复合后缀。例如：

```text
.jpg, png；PDF
```

扫描只把这些后缀计为目标文件，其他文件只统计、不移动。多个后缀同时匹配时优先采用最长后缀。

## 工作流

1. 选择源目录和目标目录。
2. 设置后缀、起始年份、每月叶目录数、每叶文件数。
3. 扫描，UI 自动显示目标文件数和容量计算结果。
4. 生成 Dry-run，检查分页预览和 TSV。
5. 确认后正式移动；需要时可按运行清单撤销最近一次移动。

目标重名会自动追加 `_dup001`。正式移动优先使用重命名；跨盘时使用复制、大小及时间校验后再删除源文件。

再次整理到已有目标目录时，Dry-run 会统计现有叶目录中的匹配文件，从第一个未满叶目录继续分配。正式移动每个文件前还会重新读取叶目录容量；若其他程序或网络用户在 Dry-run 后改变了容量，本次计划会停止并要求重新生成。

## 增量投料

“投料目录”用于选择本次新增文件的来源，投料文件使用同一套后缀和目录容量设置：

1. 选择投料目录后点击“投料 Dry-run”。
2. 程序先扫描投料文件，再审计目标目录中所有匹配后缀文件的位置和每叶数量。
3. 若目标结构正确，只把投料文件按修改时间从老到新追加到最后一个未满叶目录及后续新目录，不改变现有文件的位置。
4. 若目标结构存在错位、空洞、未填满的中间叶目录或超量叶目录，先把现有匹配文件经目标目录内的临时区按修改时间从老到新重排，再追加投料文件。
5. Dry-run 会显示投料数量、现有目标数量、整理后的目标总数、是否需要重排以及每次移动的完整 TSV 明细。

重排与投料共用一次运行清单，可整体撤销。若上次操作中断后临时区仍有文件，新投料会停止并提示先撤销或人工恢复，避免遗漏被暂存的文件。投料目录不能放在目标目录内部；目标目录可以位于投料目录内，此时扫描会自动排除目标子树。

正式移动前会在后台逐一校验全部投料源文件，并重新执行同一套目标审计，核对 Dry-run 时记录的目标文件路径、大小和修改时间快照；投料源或目标发生变化时不会移动任何文件，而是要求重新生成投料 Dry-run。这里的快照只用于判断计划是否过期，不改变上述“目录结构与每叶数量”的正确性边界。需要重排时采用失败即停策略：任一现有文件暂存或重排失败，后续操作立即停止，不会进入投料阶段。

运行清单采用预写记录：每次文件操作前先写入 `pending` 并执行文件同步，完成状态同样同步到磁盘。如果文件已经移动而完成记录因磁盘或网络故障未能写入，撤销会根据源和目标的实际状态恢复该操作；无法安全判断的歧义状态会停止自动撤销并保留恢复提示。新清单同时记录文件大小和完整范围的 RFC3339Nano 修改时间，撤销时两者都必须一致；旧版六列清单及上一版整数纳秒时间保持兼容。网络撤销读取清单和检查 `pending` 时会显示持续动画、采用网络重试并响应取消。

清单解析采用失败关闭策略：非法时间、非法大小、未知状态、列数不一致或截断记录都会阻止整次撤销，不会静默跳过或退回较弱校验。程序启动时先加载并显示普通配置，再在后台检查最近运行清单；网络检查显示动画，读取失败会写入日志，不会再阻塞路径和后缀配置的显示。

SMB、UNC 和网络映射盘的目录选择、扫描、校验及规划均在独立线程执行。目录选择器可通过主窗口取消，关闭程序也不会无限等待 Shell 对话框。扫描会逐层重试目录读取，包括网络暂时返回的“路径不存在”。网络 Dry-run 在目标规划和源目录空目录预览全部完成前保持持续动画；网络移动和撤销在单文件 I/O 期间也显示跑马灯。这些等待均不会阻塞主窗口消息循环。

扫描被取消或存在任何目录读取错误时，结果会被视为不完整并禁止生成 Dry-run。跨盘复制会同步目标内容，设置后再次核验并同步目标文件的大小和修改时间，最后才删除源文件；网络空目录清理也逐层重试并持续显示读取动画。配置写入失败会显示在 UI 日志中，不再静默忽略。大型投料重排的审计和计划循环会持续检查取消信号，不会在目录读取停止后继续长时间生成计划。

## 构建与测试

在仓库根目录运行：

```powershell
go test ./file-manager/...
.\file-manager\build.ps1
```

构建输出为 `file-manager\dist\FileManager.exe`。运行配置保存在 EXE 同目录的 `file-manager-data\config.json`。
