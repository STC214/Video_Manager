# Video Manager 文档入口

## 项目目标

Video Manager 是一个已经实现的 Windows 桌面视频归档工具，用于把大量零散视频按固定数量整理到稳定、可排序、可预览的目录结构中。

项目不做视频内容识别、标题识别、转码或标签管理。首版只基于文件系统元数据处理视频文件，并在正式移动前提供 dry-run 预览。

## 当前状态

### 增量投料

主窗口新增“投料目录”操作行：选择新文件目录后点击“投料 Dry-run”，预览和导出新增文件的目标位置，再用“开始移动”执行。投料扫描使用与普通扫描相同的视频后缀；投料前同时比对 `_video-manager/structure.json` 中保存的层级、命名、目录数量和每叶文件数，与目标中符合当前命名规则的结构目录及每叶受管视频数量。实际叶目录路径须符合原命名规则，每叶受管视频数不超过原设定上限；历史未满叶目录、编号空缺及符合原命名规则的空叶目录均保留原位，不据此拦截投料。其他不符合当前结构命名规则的目录及其中的视频不会纳入投料审计、容量计数或移动，原位保留；只校验符合完整命名规则的叶目录及其直属受管视频。普通归档模式只接收尚无视频的目标；已有归档一律使用投料模式。投料只移动新文件，从实际编号最大的末尾叶目录继续追加，满额后按原命名规则增加目录；容量不足时沿用现有规则扩展第一层。正式移动产生文件后，目标目录的 `_video-manager/structure.json` 会原子保存层级与容量设定；后续投料会严格比对。旧归档尚无此记录时，首次正式投料须明确确认当前设置是原设定。首次绑定意图原子保存于运行清单旁的 `.structure-intent.json` 文件；撤销全部本次文件后，仅在目标恢复到投料前文件快照时删除本次创建的结构记录，后续文件仍在使用时会保留。正式移动采用不替换目标文件的重命名，Dry-run 后出现的同名文件会使该项移动失败并保留双方文件。受审计的结构目录或受管文件在 Dry-run 后发生变化时，正式移动前的复审会终止旧计划；无关目录变化不影响投料计划。

投料的“每叶文件数”仅统计受管视频后缀；其他类型文件不参与容量计数，也不会被投料移动。旧归档若没有结构记录，程序可核对可见目录形态和已存文件数量，但原始未用满的目录数量无法从磁盘现状反推，因此仍需首次绑定确认。

正式投料前，在目标复审通过且持有目标移动锁后，若目标尚无 `_video-manager/archive.csv`，程序先创建一次原有受管视频基线档案（相对路径、字节数、修改时间）；不符合结构命名规则的目录和文件不入档。CSV 原子写入且不覆盖已有文件；建档失败时不开始移动。Dry-run 不改写目标；后续新增文件由每次运行清单 TSV 记录，基线 CSV 保持原样。

当前项目已经包含可运行的 Go / Win32 实现、核心自动化测试和正式 Windows GUI 构建脚本。

**删除边界说明：** 主程序没有递归删除文件的归档路径；正式移动会使源路径消失，跨卷时仅在副本验证后删除本次源文件，成功移动后还会清理空的源子目录。扫描会把源文件对象身份带入内存计划；即使外部程序替换文件后保持相同大小和修改时间，正式移动仍会检查身份，目标投料复审也会检查已有文件身份。对象标识复用、极端并发修改与断电仍是边界。详细条件见 [文件删除边界审查](docs/deletion_safety_audit.md)。重要数据正式移动前应保留独立备份。

当前已实现：

- 递归扫描视频文件并统计数量、大小和扩展名。
- 扫描在后台执行，支持忙碌进度条、节流日志和取消扫描。
- 归档容量计算器和可视化目录层级设置；先输入 1 到 8 层并应用，再逐层选择年份、季度、月份、分组、固定名称或高级自定义规则，可直接省略季度等可选层。
- dry-run 移动计划生成、空目录预览和 TSV 导出，已后台化避免 UI 卡死。
- 扫描使用持续进度动画，Dry-run 显示四阶段确定进度；日志最新消息置顶，日志与预览刷新采用无闪烁重绘。
- 源目录、目标目录或归档结构配置变化后会作废旧计划，必须重新扫描或重新生成 Dry-run，避免按过期配置移动。
- 配置容量不足时，规划器保持每叶目录文件数不变并自动增加第 1 层目录数量，不会仅因容量估算不足而禁用正式移动。
- Dry-run 因路径、权限或目标读取失败而禁用移动时，预览区、日志和 TSV 都会显示真实错误原因。
- 新一轮 Dry-run 会立即覆盖旧预览；失败或取消时预览区显示本次原因，不继续展示过期计划。
- 正式移动文件，优先 rename，失败后使用 copy + verify + delete。
- 跨盘复制后会复核源/目标 SHA-256、源文件对象身份、大小与修改时间，并确认目标元数据可保留，之后才删除本次移动的源文件。
- 大文件复制按块执行，并在块边界响应取消。
- 目标重名自动追加 `_dup001`。
- 运行清单 TSV。
- 移动无错误后只清理源根目录以下仍为空、对象身份未变化的子文件夹；保留源根目录和非空目录。
- 移动前确认弹窗和移动进度条。
- 扫描使用不确定进度条，Dry-run 使用四阶段确定进度，移动和撤销使用按文件数计算的确定进度条，并减少进度条重绘闪动。
- 移动链路的长路径封装；本地路径轻量重试，SMB / UNC / 网络映射盘使用更长退避重试。
- dry-run 阶段显示计划清理的空目录预览。
- Dry-run 预览分页显示，完整明细导出 TSV；预览与日志文本框自动换行且不显示横向滚动条，并单独使用略小字号以增加可见内容，不影响其他控件字体。
- Dry-run TSV 写入程序目录 `data/dry-runs/`，预演阶段不创建或改写归档目标目录。
- UI 日志保留最近 200 行，完整日志异步写入 `data/logs/`。
- 目录名非法字符、源目录可读性、目标目录可访问性会提前校验。
- 源目录与目标目录不能是同一路径；移动数为 0 的诊断清单不会被记录成可撤销运行。
- 浏览按钮使用资源管理器风格的 `IFileOpenDialog` 文件夹选择器，支持地址栏、侧边栏、现代导航和当前路径定位；旧系统创建失败时兼容回退。
- 程序目录 `data/config.json` 在后台自动保存和加载常用配置，不阻塞 Win32 消息循环。
- 基于运行清单撤销最近一次成功移动的文件。
- 深色 Win32 UI、深色标题栏和 EXE 图标资源。
- 标题栏与任务栏显式使用独立大小的应用图标，并通过稳定 AppUserModelID 避免任务栏身份回退。
- 构建时自动生成精确到分钟的版本号，标题栏与 Windows 文件属性使用相同版本和应用信息。

当前残余限制：

- 目录选择使用系统 Shell 的资源管理器式对话框，并在独立 UI 线程中打开；失效的 SMB 最近位置或第三方 Shell 扩展拖慢对话框时，主窗口仍可响应取消和关闭。
- SMB 单次系统 I/O 调用本身可能阻塞，程序可在任务边界和复制块边界响应取消，但不能强行中断所有 Windows 底层阻塞。
- 本机与网络盘之间的跨卷移动会跳过无意义的重命名长重试，直接使用 8 MiB 顺序缓冲复制；仍保留目标校验、落盘同步、运行清单和撤销安全。
- 网络 Dry-run、移动、撤销、空目录清理和最近运行清单检查会显示持续动画；普通配置先加载，不等待网络清单检查。取消或含读取错误的扫描结果会被视为不完整并禁止生成 Dry-run。
- “最近运行清单检查完成，可以撤销”是启动后的异步撤销状态检查，与本次投料 Dry-run 的目标结构审计相互独立；投料 Dry-run 日志现在显示专用的四阶段名称。

File Manager 的目录层数、逐层命名选项、示例和高级规则，请阅读 [file-manager/README.md 的“目录层级和命名”](file-manager/README.md#目录层级和命名新手也可以直接照着设置)。该说明按“输入层数 → 应用 → 逐层选择 → 查看示例 → 重新生成 Dry-run”的顺序编写。

## 归档模式概览

### 两层模式

适合中小规模视频目录。

```text
Animation/
  Season_001/
    Episode_001/
    Episode_002/
```

默认参数：

```text
每个 Episode 最多 25 个视频
每个 Season 包含 4 个 Episode
```

### 三层模式

适合大规模视频目录。

```text
VIDEO/
  Arc_01/
    Season_001/
      Episode_001/
      Episode_002/
```

默认参数：

```text
每个 Episode 最多 30 个视频
每个 Season 包含 5 个 Episode
每个 Arc 包含 10 个 Season
```

## 统一规则

- 目录编号使用补零格式，保证 Windows 资源管理器中排序稳定。
- `Episode` 和 `Season` 默认使用三位数，例如 `Episode_001`、`Season_001`。
- `Arc` 默认使用两位数，例如 `Arc_01`。
- 源目录内部原有目录名不参与分类判断；程序只递归扫描文件，再按稳定顺序重新分组。
- 文件按最后修改时间从早到晚分配；越早的文件进入编号越小的叶目录。修改时间相同时，再按相对路径和文件名升序保证结果稳定。
- 正式移动前会复核源文件大小和修改时间；扫描或 Dry-run 后发生变化的文件不会按旧计划移动。
- 每个叶目录的文件数是“最多 N 个”；普通首次归档通常只有最后一叶未满，投料会保留历史未满叶目录且只向实际末尾追加。
- 默认保留原文件名，不按内容重命名。
- 目标重名时追加 `_dup001`、`_dup002`。
- 清理阶段只删除确认为空且身份未变化的源子目录；源根目录、非空目录和普通文件保留。
- 不处理非视频文件，除非用户明确开启相关规则。

## 文件系统支持

首版必须支持 Windows 能正常访问的文件系统路径，包括：

- 本地磁盘路径，例如 `D:\Videos`。
- 软路由或 NAS 通过 SMB 挂载后的盘符路径，例如 `Z:\Videos`。
- SMB / UNC 路径，例如 `\\router\share\Videos`。

工具不直接实现 SMB 协议，只通过 Windows 文件系统 API 访问已认证、已挂载或可访问的网络路径。

## 构建

正式 EXE 必须从项目根目录使用统一脚本构建：

```powershell
.\build.ps1
```

默认输出为 `dist\VideoManager.exe`。脚本会按本机当前时间生成 `yyyyMMdd_HHmm` 格式版本号，例如 `20260711_1035`，并同时写入：

- 窗口标题栏：`Video Manager - 20260711_1035`。
- Windows 文件属性中的文件版本和产品版本。
- 产品名称、文件说明、公司、版权和原始文件名等应用信息。

不要使用裸 `go build` 生成正式发布文件，因为裸构建不会刷新 Win32 版本资源和标题栏版本。

维护验证命令：

```powershell
go test ./...
go test -race ./...
go vet -unsafeptr=false ./...
```

Win32 窗口过程必须把 `lParam` 转换为系统提供的结构体指针，因此标准 `go vet ./...` 的 `unsafeptr` 分析会对 `WM_DRAWITEM` 和 `WM_GETMINMAXINFO` 两处 ABI 转换给出预期告警；其余 vet 规则仍需通过。

启动阶段默认不创建日志文件，任务日志在首次使用时懒加载。需要诊断启动阶段时，可临时设置 `VIDEO_MANAGER_STARTUP_TRACE=1`，轨迹会写入 `data/logs/startup.log`。

## 仓库内容

仓库保留：

- `cmd/`、`internal/` 和 `tools/` 下的 Go 源码与测试。
- `assets/app.ico` 正式应用图标。
- `build.ps1` 正式构建入口。
- `README.md` 和 `docs/` 项目文档。

以下内容由 `.gitignore` 排除，不应提交：

- `dist/` 中的 EXE、运行配置、日志、Dry-run TSV 和其他运行数据。
- 构建生成的 `cmd/video-manager/app.syso`、`.build/` 和本地 Go 缓存。
- `.agents/`、`.codex/`、编辑器配置和操作系统元数据。
- 已转换完成且构建不再依赖的根目录原始图片 `ico.png`。

干净检出后运行 `.\build.ps1` 会重新生成 Win32 资源和 `dist/VideoManager.exe`。

## 维护约束

归档核心逻辑继续保持在无 UI 的 Go 包中，并用 [docs/test_cases.md](docs/test_cases.md) 中的场景验证扫描、规划、重名处理、dry-run、移动、撤销和清理逻辑。UI 层只负责配置、预览、进度和日志展示；Win32 消息循环必须固定在同一系统线程，文件和网络 I/O 不得进入 UI 线程。
